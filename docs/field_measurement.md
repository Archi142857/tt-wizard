# 오르막 실측 — 측정 방법과 기록 양식

경사 반영 이동시간(`docs/travel_time_method.md`)이 실제 걷는 시간과 맞는지 오르막 구간을 직접 걸어 잰다.
확인하려는 것은 '몇 분 걸리나'가 아니라 '경사 때문에 몇 % 느려지나'다. 같은 사람이 오르막·내리막·평지를 걸으면
그 사람의 걷는 속도는 나눗셈으로 지워지므로, 사람마다 속도가 달라도 경사 효과는 잴 수 있다.

폰 하나로 재는 **측정 페이지(GPS)** 를 먼저 쓴다. 페이지를 못 쓰면 스톱워치로 잰다(아래 '스톱워치로 재기').

```bash
python scripts/field_validation.py track data/field/tracks              # 측정 페이지 기록 → results/field/ (구간 시간 + 경사별 속도)
python scripts/field_validation.py suggest                              # 경사로 시간이 많이 느는 강의 건물 쌍 (평지 15분 이하)
python scripts/field_validation.py plan --routes data/field/routes.csv  # → results/field/plan.md, plan.csv, plan.geojson
python scripts/field_validation.py check data/field/measurements.csv    # 스톱워치 기록 → results/field/README.md, CSV, 그림
```

## 측정 페이지 (폰, GPS)

주소: https://archi142857.github.io/tt-wizard/field/ (앱 화면에서는 링크하지 않는다). 설치 없이 폰 브라우저로 연다.
아이폰은 Safari 탭으로 연다(홈 화면에 설치한 앱으로 열면 iOS 18.4 미만에서 화면 유지가 안 된다).

1. **걷는 사람**: 처음 한 번 글자(A~F)를 고른다. 같이 재는 사람끼리 다른 글자. 이름은 적지 않는다.
2. **구간**: 추천 구간(R1~R4)의 방향 버튼을 누르면 지도에 모형 경로(파란 선), 출발 출입구(초록), 도착 출입구(빨강)가 나온다.
   예상 시간은 보여 주지 않는다(보고 걸으면 맞추게 된다). '다른 구간 고르기'로 아무 건물 쌍이나 고를 수도 있다.
3. **위치 켜기** → GPS 오차가 '좋음'(±15 m 이하)이 될 때까지 몇 초 기다린다.
4. 출발 출입구 문 앞에서 **출발**. 파란 선을 따라 평소 수업 갈 때의 속도로 걷는다. 뛰지 않는다. 가방은 평소처럼.
   화면을 켠 채 손에 든다(페이지가 화면 꺼짐을 막는다. 꺼지거나 다른 앱으로 가면 그동안은 위치가 비고 시간은 그대로 잰다).
5. 신호 대기·계단 정체는 멈추지 말고 그대로 둔다. 멈춘 시간은 분석에서 GPS 속도로 찾아 뺀다.
6. 도착 출입구 문에 닿으면 **도착을 길게(0.8초) 누른다**. 누르기 시작한 순간이 도착 시각이다. 날씨·메모를 적고 저장.
   저장하면 돌아오는 방향이 바로 골라진다.
7. 측정한 날 **내보내기**(공유) 또는 **파일로 받기** → CSV 하나. PC의 `data/field/tracks/` 에 넣거나 채팅에 첨부한다.
   폰의 기록은 지울 때까지 남고, 같은 기록을 여러 번 내보내도 분석은 하나로 친다.

페이지가 새로고침되거나 닫혀도 걷던 기록은 5초마다 저장돼 있어 '이어서 기록'할 수 있다(끊긴 동안은 위치가 빈다).
기록은 그 폰의 브라우저 저장소에만 있다. 서버로 보내지 않는다.

### 추천 구간 (`data/field/routes.csv`, 페이지와 같다)

| 구간 | 출발 → 도착 | 길이 | 높이차 | 길 |
| --- | --- | --- | --- | --- |
| R1 공대 오르막 | 39 대학원연구동 → 301 제1공학관 | 534 m | +55.5 m | 도로 오르막 |
| R2 계단 | 15 법학관1 → 12 사범교육협력센터 | 429 m | +31.3 m | 계단 약 210 m |
| R3 평지 | 12 사범교육협력센터 → 21 약학관1 | 383 m | +1.2 m | 평지 (사람마다 평지 속도) |
| R4 경영대 오르막 | 58 SK경영관 → 223 우석경제관 | 349 m | +26.8 m | 도로 오르막 |

- 넷 다 '경로 다름'(마법 지도 표와 우리 경로가 크게 다름)이 아니다. 갔다가 같은 길로 돌아온다(양방향).
- 순서: R4 왕복 → (370 m) → R2 오르막 → R3 왕복 → R2 내리막 → (850 m) → R1 왕복. 한 바퀴에 1시간 남짓.
- 한 사람이 한 바퀴만 걸어도 된다. 다른 날 한 바퀴 더, 친구 두세 명이 한 바퀴씩 걸어 주면 더 좋다(링크만 보내면 된다).

### 분석 (`track`)

```bash
python scripts/field_validation.py track data/field/tracks      # 폴더 안 CSV 전부 (파일을 여러 개 적어도 된다)
python scripts/field_validation.py track data/field/tracks --dem data/dem   # 고도 단면을 DEM 으로 (기본: data/dem 이 있으면 쓴다)
```

- **경로 위 위치.** GPS 점(오차 25 m 넘는 점은 뺀다)을 모형 경로 위로 옮기고, 앞뒤 8초를 평균한 뒤 앞으로만 가게(단조 증가)
  맞춘다. 출발(시간 0, 위치 0)과 도착(끝 시각, 경로 끝)은 거의 정확히 안다. 점의 80 % 넘게가 경로 20 m 안에 있지 않으면
  다른 길로 걸은 것으로 보고 뺀다. 평균 2.5 m/s 넘게 빠르면(뛰었거나 탈것) 뺀다.
- **멈춘 시간.** 폰이 주는 속도(GNSS 도플러)가 6초 넘게 0.35 m/s 미만인 때. 속도를 안 주는 폰은 20초 동안 4 m 도 못 간 때
  (이때는 짧은 멈춤을 못 잡는다). 구간 시간(`data/field/measurements_gps.csv`, `check` 입력)은 멈춘 시간을 뺀 값이고,
  전체 걸린 시간은 `gps_walks.csv` 의 `total_s` 다. 그다음은 '분석 (check)' 과 같다.
- **경사별 속도.** 경로를 50 m 조각으로 나눠 조각마다 걸린 시간을 잰다(멈춤·끊김이 있는 조각은 뺀다).
  사람마다 평지 속도를 1로 두고 조각 경사별로 실측 속도를 Tobler 식(k = 3.5)과 견준다. 계단 조각(절반 넘게 계단)은 따로 본다.
- **경사 계수 맞추기.** 속도 식 v = v0 · exp(−k |g + 0.05|) / exp(−0.05 k) 에서 k 를 0~8 사이에서 고르고 사람마다 v0 를
  맞춰, log(실측 ÷ 예측) 제곱합이 가장 작은 k 를 찾는다. k = 0 이면 평지 모형, 3.5 면 Tobler. 경사를 재는 창 길이
  (10·20·30·50 m)별로 남는 차이도 낸다.
- 결과: `results/field/README.md` 의 'GPS 기록' 절, `gps_walks.csv`(기록별), `gps_chunks.csv`(조각별), `gps_summary.json`,
  `fig_field_grade`(경사별 속도). 위치(위도·경도) 원자료는 결과에 남기지 않는다. `data/field/tracks/` 는 git 에 올리지 않는다.
- 가짜 기록(R1~R3 왕복, 두 사람, GPS 오차 3 m·상관시간 15초, 난수 씨앗 4개)으로 확인하면 사람별 평지 속도는 1 % 남짓 안,
  k 는 3.55~3.65(참값 3.5), 30초 멈춤은 27~28초로 되찾는다. 오차 4 m·상관시간 20초에 폰 속도가 없을 때도 k 는 3.45~3.65
  (`tests/test_field.py`).

## 스톱워치로 재기 (페이지를 못 쓸 때)

### 구간 고르기

- 오르막이 뚜렷한 구간 3~5개. 가능하면 **양방향**을 다 잰다. 오르막 ÷ 내리막 시간 비가 평지 모형(1)과 경사 모형 중
  어느 쪽에 가까운지가 가장 깔끔한 검증이다.
- 비교용으로 거의 평평한 구간 하나를 넣으면 사람마다 다른 걷는 속도를 따로 가늠할 수 있다.
- `suggest` 의 `check` 칸에 '경로 다름'이 붙은 구간은 마법 지도 표와 우리 경로가 달라서 피한다.

### 걷는 법

1. `plan` 결과의 **출발점(출입구)** 에서 시작해 `plan.geojson` 의 길을 그대로 따라 **도착 출입구**까지 간다.
   모형이 계산한 길과 다르게 걸으면 비교가 안 된다(지름길·다른 출입구·엘리베이터 금지).
2. 평소 수업에 갈 때의 속도로 걷는다. 뛰지 않는다. 가방은 평소처럼.
3. 출입구 문을 나서는 순간 스톱워치를 켜고, 도착 출입구 문에 닿는 순간 끈다.
   횡단보도 대기·계단 정체도 그대로 포함하고, 있었으면 `note` 에 적는다.
4. 같은 구간·방향을 사람마다 **3번 이상**. 되도록 두 사람 이상, 다른 날·다른 시간대에.

### 기록 양식 (UTF-8 CSV)

`data/field/routes.csv` — 잴 구간 (`routes_template.csv` 와 같은 열. 지금은 추천 구간 R1~R4)

| 열 | 뜻 | 예 |
| --- | --- | --- |
| `route` | 구간 이름 | `R1` |
| `from`, `to` | 출발·도착 동 번호 (앱과 같은 표기. 정문 `GATE`, 기숙사 `919`) | `GATE`, `302` |
| `note` | 메모 | `정문→공대 오르막` |

`data/field/measurements.csv` — 측정 한 번이 한 줄 (`measurements_template.csv` 를 복사)

| 열 | 뜻 | 예 |
| --- | --- | --- |
| `route` | 구간 이름 (`routes.csv` 에 있으면 `from`·`to` 는 비워도 된다) | `R1` |
| `from`, `to` | 출발·도착 동 번호 | `GATE`, `302` |
| `date`, `start_time` | 날짜, 출발 시각 | `2026-10-03`, `14:05` |

| `note` | 횡단보도 대기, 계단 정체, 짐 등 | `신호 40초 대기` |

## 분석 (`check`)

- **예측값.** 실측과 같은 길인 우리 경로의 경사 반영 시간(`route_slope_min`)과 평지 시간(`route_flat_min`),
  앱이 쓰는 값(마법 지도 표 × 경사 계수), 마법 지도 표(평지). 모두 평지 1.1 m/s 기준이다.
- **오차.** 실측 − 예측(분)의 MAE·평균·RMSE.
- **사람별 속도 보정.** 걷는 속도는 사람마다 달라서 1.1 m/s 기준 오차에는 그 차이가 섞인다. 측정마다
  경사 보정 속도 v0 = 1.1 × 경사 반영 예측 ÷ 실측(모형이 이 속도였다면 실측과 같았을 평지 속도)을 구하고,
  사람마다 중앙값으로 속도를 하나 맞춘 뒤 남는 차이를 본다. 평지 모형도 같은 방법(거리 ÷ 시간의 중앙값)으로 맞춘다.
  **경사 모형이 맞다면** 오르막·내리막 구간이 섞여도 v0가 고르게 나오고(변동계수가 작고),
  보정 뒤 남는 차이가 평지 모형보다 작다.
- **오르막 ÷ 내리막.** 양방향을 잰 구간은 실측 시간 비를 경사 모형의 비, 평지 모형의 비(1)와 견준다.
- 결과: `results/field/README.md`(요약), `validation_trials.csv`(측정별), `validation_routes.csv`(구간별),
  `validation_summary.json`, `fig_field_scatter`(실측 vs 예측), `fig_field_speed`(구간별 속도).

## 한계

- 몇 사람이 몇 구간을 몇 번 걷는 소규모 측정이다. 속도 보정도 같은 자료로 맞춘 값이라 낙관적이다.
- 스톱워치 반응 시간(±1초), 신호 대기처럼 모형에 없는 시간이 섞인다(GPS 기록은 멈춘 시간을 찾아 뺀다).
- 폰 GPS 는 몇 m 흔들리고 그 오차가 수십 초 이어진다. 50 m 조각 하나의 시간은 10 % 안팎 틀릴 수 있어 조각을 모아서 본다.
  높은 건물 사이·산 옆(공대 쪽)에서는 더 흔들린다.
- 고도 단면은 모형과 같은 DEM(수치지형도 2 m 격자)이다. 계단 하나하나나 다리 위 높이는 담지 못한다(`docs/elevation_method.md`).
- 가을 한 시점의 측정이다. 날씨·짐·피로에 따라 달라진다.
